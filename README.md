# BCOP Dialogue Core

BCOP — помощник человеку в последовательном диалоге с банком или коллектором.

Рабочий сценарий текущего вертикального среза:

> новое сообщение собеседника → история диалога + цель пользователя → анализ тактик → три безопасных черновика ответа → выбранный черновик сохраняется в историю.

Юридические и доказательные функции пока являются вспомогательными. BCOP не утверждает нарушение только по одному сообщению и не заменяет проверку документов специалистом.

## Запуск

```bash
pnpm install
cp .env.example .env
pnpm build
pnpm start
```

Откройте `http://localhost:8787`.

Для разработки в отдельных процессах:

```bash
pnpm dev:api   # API на 8787
pnpm dev       # Vite на 5173, /api проксируется на 8787
```

По умолчанию включён `DEMO_MODE=true`: сервер работает без ключа и явно помечает результат как «ДЕМО». Для реального AI-контура задайте `OPENAI_API_KEY` серверу и установите `DEMO_MODE=false`.

## Безопасность текущего среза

- OpenAI SDK и ключ отсутствуют в браузерном bundle.
- API-ключ читается только из `OPENAI_API_KEY` на сервере.
- Перед каждым анализом пользователь видит обезличенную копию нового сообщения и подтверждает передачу.
- Клиент и сервер независимо маскируют распространённые идентификаторы: телефон, email, карту, счёт, СНИЛС, номер документа/ИНН и часть форматов ФИО.
- По умолчанию исходная история остаётся только в памяти вкладки. Её сохранение в `localStorage` — отдельный opt-in; все диалоги можно удалить одной кнопкой.
- История передаётся в API явно, ограничивается по числу сообщений и размеру.
- Запрос к OpenAI использует `store: false` и Structured Outputs.
- API-ответы имеют `Cache-Control: no-store`; серверный журнал содержит только request ID, статус, режим и длительность, без текста переписки.
- `/api/dialogue/analyze` защищён лимитом запросов, настраиваемым через `RATE_LIMIT_MAX_REQUESTS` и `RATE_LIMIT_WINDOW_MS`.
- Текст переписки рассматривается моделью как недоверенные данные.
- Варианты ответа не содержат угроз, оскорблений и провокаций.

```bash
pnpm test

```

## Публичное мобильное демо

Для показа интерфейса без сервера и без приёма реальных текстов есть отдельная статическая сборка:

```bash
pnpm check:public-demo
```

В ней доступны только три вымышленных сценария; поле ввода, хранение истории и API-клиент отсутствуют. Workflow GitHub Pages публикует текущую Draft-ветку после включения источника **GitHub Actions** в настройках Pages. Полная схема и мобильная приёмка: [`docs/public-mobile-demo.md`](docs/public-mobile-demo.md).
